# `standalone_repo/` — assembles the reproduction repository

This folder does not run any science. It packages the working tree into a standalone
repository a reviewer can clone: code, tier-A data, a checksummed manifest, and the scripts
to fetch the rest.

```bash
julia --project standalone_repo/build_repo.jl              # → ../physics-informed-priors-repro
bash   standalone_repo/make_tierB_archive.sh               # → the 7.9 GB archive (generated by the above)
```

`SKIP_HASH=1` skips the SHA-256 of tier B, which hashes 7.9 GB and takes minutes — useful
while iterating, never for a real build.

## The tier split

| tier | size | what | where it lives |
|---|---|---|---|
| code | 2.4 MB | `src/`, the pipeline folders, the two shared libraries | committed |
| A | 23 MB | the three models **without** their design matrices, every θ vector, the serialised band curves, the NPT summaries | committed |
| B | 7.9 GB | the three `A.csv` (7.4 GB of it), the 73k constrained cloud, the cached Hessians, the DFT datasets | archive, fetched and checksummed |

The line between them is **replot vs re-derive**. Tier A alone rebuilds every figure in the
paper from saved parameters — verified: a clean build into an empty directory reproduces
`bands_four_panel.pdf` at the same byte size as the published one, with nothing fetched.
Tier B is only needed to re-solve the constrained optimisations.

Two tier-B entries are marked `rebuildable`: the 429 MB undotted Hessian and the Al_16 band
path are caches, regenerable from the rest, so a fetch may legitimately skip them.

## `manifest.jl` is hand-written; `data/manifest.toml` is generated

`manifest.jl` declares *what belongs in which tier and which script produces it* — that is a
judgement, so it is written by hand and kept short. `data/manifest.toml` adds the mechanical
facts (SHA-256, byte count) and is regenerated on every build. `paper_figures/manifest.jl`
in the source repo is the ancestor of this idea; at 47 KB hand-maintained it is exactly the
thing that drifts, which is why only the judgement half survives here.

`build_repo.jl` fails loudly on a declared file that does not exist, so the manifest cannot
silently rot.

## The `.gitignore` trap

The source repository's `.gitignore` excludes `*.csv`, `*.json`, `*.xyz` and `models/` —
which is **the whole of tier A**. Copied across, the new repository would look complete and
contain no data at all. `build_repo.jl` therefore writes a fresh `.gitignore` derived from
the tier split, with a comment saying exactly this. Do not replace it with the source one.

## What to check before deposit

```bash
cd ../physics-informed-priors-repro
git init && git add -A && git status --short | wc -l     # ~115 files, ~25 MB
julia --project -e 'using Pkg; Pkg.instantiate()'
bash run_all.sh replot                                   # every figure, tier A only
bash scripts/fetch_data.sh verify                        # after the archive is in place
```

The `TIERB_URL` baked into `scripts/fetch_data.sh` is a placeholder until the archive is
deposited — set it at build time (`TIERB_URL=https://... julia --project standalone_repo/build_repo.jl`)
or edit the one line afterwards.
