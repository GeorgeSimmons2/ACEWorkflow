💡 KEY INSIGHTS:
════════════════

  1. POPS creates ensemble where EACH member passes through ONE data point
     → 50 data points = 50 ensemble members
     → Each member: θᵢ solves: min ||θ - θ_nominal||² s.t. X_i'θ = y_i

  2. Add inequality constraints to each member:
     → Enforce bounds: -1.2 ≤ p(x) ≤ 1.2
     → Enforce smoothness: -2 ≤ dp/dx ≤ 2
     → Enforce positivity: y ≥ 0
     → Each member still passes through its data point!

  3. Trade-offs emerge:
     → Training fit slightly worse (but near-perfect within solver tolerance)
     → Generalization dramatically better (14-29% improvement)
     → This is EXPECTED and DESIRABLE in misspecified models

  4. Constraints help MOST when:
     → Model severely misspecified (oscillatory data vs polynomial)
     → Extrapolation/generalization important
     → Physical bounds known (e.g., probabilities ∈ [0,1])
     → You care about predictions beyond training range


🔧 TECHNICAL SUMMARY:
══════════════════════

  Algorithm: POPS with inequality constraints via quadratic programming
  
  Solver: OSQP (Operator Splitting QP)
    • Sparse matrix format
    • First-order method (efficient)
    • Settings: eps_abs=1e-4, eps_rel=1e-4, max_iter=10000
    • Per-point solve: independent (embarrassingly parallel)
    • Typical solve time: 10-50 iterations
  
  Language: Julia 1.x
  Dependencies: OSQP, SparseArrays, LinearAlgebra, Statistics, CairoMakie
  
  QP Formulation (for each training point i):
    minimize:   ||θ - θ_nominal||²
    subject to: X_i' θ = y_i           (equality: pass through point)
                ℓ_j ≤ (A θ)_j ≤ u_j    (inequality: constraints)
